# PawOffice 成果阅读器 · 视觉设计说明

本轮交付是一份独立的高保真视觉原型。HTML 可直接双击打开，样式、图标、样例与图片全部内嵌，不需要安装依赖或连接服务。它展示固定设计场景，不是生产组件或通用数据渲染器。

## 1. 设计主张

把成果阅读器设计成办公室里一份可以认真阅读的交付简报：先读清本轮变化，再打开交付物，随后核对证据，最后理解演进与下一步。

保留 PawOffice 首页的暖白、灰绿、轻边界与友好圆角；将空间感转化为纸张、文件陈列、正文与旁注之间的关系。办公室形象只出现在品牌与参考素材中，不把 2D 场景变成正文背景。

两种阅读形态共享品牌、工具栏、字体、状态语义、文档阅读器，但拥有不同的内容重心：

- **交付物型**：本轮变化 → 文件集合 → 少量关键观察 → 变更 → 验证与风险 → 版本与工作记录。
- **事实描述型**：标题与结论 → 论述与引用 → 相关观察 → 证据边界 → 后续建议。文献只是证据入口，不强造一套交付文件目录。

原型顶部的场景选择和设备按钮属于评审工具，不属于产品导航；三个场景不是重新引入三个业务分类 Tab。

## 2. 研究依据与内容来源

研究了首页布局、现有成果阅读组件、样例字段，以及现有八张类型截图 `type-01` 至 `type-08`。观察到的主要问题不是颜色，而是大部分内容以相近的行高、标签、分隔方式出现：文档缺少阅读身份，指标类型差异不足，验证结论与发布状态容易混读，长文被字段结构切碎。

本轮主要来源：

| 来源 | 使用范围 |
| --- | --- |
| `apps/web/src/dev/fixtures/result-ready-round3.json` | 登录模块交付样例、当前文档原文、指标、检查、风险、变更、版本及工作记录 |
| `apps/web/src/dev/fixtures/whiteboard-ready-round3.json` | 历史需求说明 v1.0，用于真实原文阅读与视觉版本对照 |
| `docs/design/result-board/screenshots/type-01-metrics-kinds.png` 至八张类型样例 | 现有数据类型与表现形式的设计研究 |
| `docs/design/result-board/screenshots/01-home-1787x864.png` | 首页配色与空间关系参考；原型内图片示例 |
| `public/brand/icon.png` | 既有 PawOffice 品牌图标 |

这里的“提供的真实样例”指仓库已有 fixture 的真实内容，并不代表线上真实业务结果。交付页保留原始模拟数据语境；不把 mock 文案包装成已执行的检查。

事实报告是**设计 fixture**：叙述、结构与建议为设计演示，明确标记；其中引用的文档句子来自现有样例。组件图谱内补充的比较指标、图表、API、环境、列表与草稿/回退状态等也属于设计 fixture。图片沿用现有首页截图，没有伪造产品运行画面。示例链接不会跳转外部网站。

当前三份文档和历史需求说明的原文被保存在独立 HTML 内。纸张缩略图只承担预览作用；阅读弹层提供完整正文、原文、下载及需求版本对照。对照是依据这两份固定原文预先编排的视觉样例，不是新增 diff 引擎。

## 3. 整体布局与首屏

桌面阅读器最大宽度 1232px，内侧主要留白 58px，形成一张明确的阅读纸面。外部灰绿空间与首页呼应，不继续叠套多层卡片。

交付页将原来的普通摘要提升为 30px 的首要内容，成果名称作为较小的题签。读者先看到“需求说明更新至 v2.0，新增验收报告；接口文档 v1.0 继续保留”，而不是先辨认字段。

首屏右侧 248px 审阅旁注同时显示“已交付，尚未验证”、待处理检查、旧版证据和未关闭风险。状态与正文同屏，避免只看到绿色发布状态。

文件集合紧接摘要。需求说明有可识别的纸张预览与直接阅读按钮，接口文档、验收报告采用紧凑的伴随文件排布。这里强调需求说明，是本轮摘要明确指出了它的更新；这不构成“列表第一个文件永远是主交付物”的业务规则。

只有三项与交付直接相关的指标进入首屏下缘。其他内容沿单页自然展开。六项文件变更默认收起，读者选择文件后再进入代码内容。

首屏设计意图是在五秒内回答：

| 问题 | 首屏位置 |
| --- | --- |
| 本轮完成了什么 | 大字号变化摘要 |
| 产生了什么 | 三份文档及其版本、阅读入口 |
| 是否已经验证 | 独立审阅旁注，不依赖成果发布标签推断 |
| 还有什么问题 | 待处理、待补充验证与风险数量，并可定位至证据 |

这是一项视觉可读性自检，尚未进行真实用户的五秒可用性研究。

## 4. 视觉基础规则

### 颜色

| 用途 | 色值 | 使用约束 |
| --- | --- | --- |
| 主要文字 | `#29362E` | 标题、重要事实、文件名 |
| 正文 | `#515D54` | 连续叙述与说明 |
| 次要文字 | `#758076` | 日期、类型、版本辅助信息 |
| 阅读纸面 | `#FFFFFF` / `#FFFEFA` | 主阅读区与纸张预览 |
| 页面背景 | `#EAECE6` | 桌面外部空间 |
| 分割线 | `#E3E7DF` | 区分章节与行，避免给每个段落加框 |
| 鼠尾草浅底 | `#EDF2E7` | 主操作、选中、通过状态的轻量背景 |
| 鼠尾草强调 | `#4B684E` | 阅读入口与积极语义文字 |
| 待处理 | `#927037` / `#FAF5E9` | 琥珀文字与浅底 |
| 风险/失败 | `#A56453` / `#F9EEEA` | 克制的砖红文字与浅底 |
| 说明信息 | `#647F8C` | 中性提示，与通过语义分开 |

颜色必须与文字、图标或纹理共同表达状态。旧版证据使用斜纹分段和“待补充验证”，不靠黄色猜测含义。不使用红绿区分代码的唯一信息，保留 `+`、`−` 与旧/新行号。

### 字体与尺度

- 使用系统中文字体：PingFang SC、Microsoft YaHei、system-ui；不加载远程字体。
- 主摘要 30px / 1.6；报告标题 35px / 1.5；移动端分别为 24px 和 28px。
- 专业文章正文 15px / 1.95，导语 17px / 1.9；移动端保持 15px 正文。不能把手机正文一并缩成元信息字号。
- 章节标题 19–22px，文件名称 15–18px，操作与短说明 12–14px。
- 11px 左右的字体只服务版本、来源、日期等低优先级信息；纸张缩略图的小字只是视觉预览，完整阅读入口必须紧邻。
- 指标采用等宽数字，主要值 31–40px；单位缩小并保持基线关系。Consolas / SFMono-Regular 用于路径、版本标识、代码与 API，不用于大段中文。

### 留白、边界和形状

- 使用 4px 附近的基础节奏，主要空间层级为 8 / 12 / 16 / 24 / 32 / 40 / 56px。
- 章节间主要靠留白与一条细线；组件内部不重复添加外框。
- 外阅读器圆角 20px，弹层 16px，文件强调区约 13px，主要操作 9px，状态标签 5px。
- 圆角属于阅读器、操作与少量有含义的强调区域，不能把每段正文都卡片化。
- 图标为 16–20px、1.6px 线宽的同一套内嵌 SVG 语言。品牌图标沿用原文件。

## 5. 五个重点组件

### 文件交付

文件不是一串附件字段。主文件具有封面式内容预览、名称、版本、摘要和阅读动作；其余文档用图标、版本与行内入口快速扫描。文件集合共同占据一块阅读区域，避免三个等大卡片争夺注意力。

阅读弹层在桌面采用 980 × 760px 上限，正文纸面最大 720px。标题、版本选择、原文/对照/下载保持在内容上方。历史文档有明确的历史提示，切换版本不会把旧内容标成当前交付。移动端采用全屏文档，正文在弹层内部滚动。

### 指标

| Metrics 类型 | 视觉结构 | 原因 |
| --- | --- | --- |
| value | 数值与单位一组，标签和解释在旁或下方 | 表达独立事实，不虚构趋势 |
| comparison | 灰色前值 → 当前值，另列差值 | 同时看到比较基准与变化，避免只给一个箭头 |
| status | 状态图标、可读状态词及上下文 | 状态不是数值，不使用数字型字号占位 |
| target | 当前值、目标文字、进度值与细条 | 目标和进度各有标签；不能把不同概念混成一个百分比 |
| text | 一句可读事实，较小标题级别 | 保留语句完整性，不把短句放大成 KPI |
| auto | 按已提供信息组合值、前值和目标 | 演示组合表现，不新增自动推断逻辑；不能为选模板而隐藏字段 |

趋势方向与好坏不是同一件事。DSH 应沿用提供的业务语义，不能一律将上涨涂绿。目标指标没有目标时，不补造“已达标”。

### 验证与风险

左侧用 **2 / 4 项标记通过** 和四段刻度解释检查分布，右侧逐项保留检查证据。2 项当前通过、1 项待处理、1 项旧版证据分别可辨；不会把旧需求 v1.0 的通过记录算进当前 v2.0。

验收意见与检查清单分开，风险以严重度、问题、处置上下文、负责人和状态形成一条完整记录。主样例的中风险保持原意；高、低风险与关闭折叠行为在组件场景演示并标记 fixture。

成果状态 `ready` 展示为“已交付”，不等于“已验证”。任务状态未提供时明确保留缺失信息。通过率 96% 是样例指标，不代替验收结论。

### 版本演进

细线串联两轮真实交付记录。时间与负责人位于左侧，每轮变化占右侧主体；当前节点有轻量外环，“本轮”与“已发布”是两种独立标签。

历史阅读和 v1.0 → v2.0 对照直接放在相关节点中。决策与任务进展置于旁侧工作记录，在移动端顺接时间线之后。组件图谱补充草稿、已发布与回退节点，不替换主样例的真实历史。

### 代码 diff

白色阅读底，鼠尾草文件标题和浅绿新增、浅砖红删除；旧行号、新行号、符号、代码形成四列。文件路径是最主要的定位信息，修改类型与增删量为辅助。

采用统一 diff，避免在窄屏把代码挤成两栏。代码保持空格与换行，长行在局部横向滚动；行号不可与代码一起复制。每个文件单独展开，二进制文件显示明确说明；Escape 可收起当前差异。没有深色 IDE 的工具栏、迷你地图或无关审查操作。

## 6. Artifacts 与 Sections

| Artifacts 类型 | 设计形态 |
| --- | --- |
| document | 纸张预览 / 文档行，名称与版本紧邻，进入完整阅读器 |
| image | 原比例缩略图、来源说明，点击查看大图；不把内容图裁成装饰封面 |
| link | 外链图标、可读标题、域名与跳转提示；演示地址明确标记 |
| data | 数据文件身份、格式、字段/记录预览和打开入口；原型中为可查看原文的 JSON fixture |

| Sections 类型 | 设计形态与理由 |
| --- | --- |
| gallery | 一个主要画面与辅助预览形成大小关系，每张图有说明；不是附件表 |
| documents | 文件集合与阅读目录，不把全文塞进单行；交付页可直接阅读，组件页演示集合 |
| tests | 检查图标、名称、版本上下文与结果组成证据清单，不用统计卡代替检查项 |
| api | 请求方法标识 + 等宽路径 + 说明 + 状态，表达接口的调用身份 |
| environments | 环境名称与状态先行，地址、版本等信息次之，使用紧凑定义列表 |
| files | 轻量文件目录，类型、名称、路径/体积等元信息对齐，避免等大文件卡 |
| changes | 可展开文件差异目录，打开后切换为代码阅读结构 |
| custom | 使用正文网格组合不同块，表格和图表可跨栏，段落不被统一卡片包裹 |

## 7. Custom Blocks

| 类型 | 视觉规则 |
| --- | --- |
| heading | 23 / 17 / 15px 建立相对层级，标题本身不额外加容器 |
| text | 连续段落、强调和引用；正文与依据相邻 |
| keyValue | 左侧固定宽度标签、右侧自然伸展值；长内容可换行 |
| stats | 一条共享基线的数字带，细分隔；不复制三个独立卡片 |
| table | 表头低强调、行分隔、数值右对齐；长表在局部滚动，保持列关系 |
| list | 列表结构与状态图标配合，文字仍是阅读主体 |
| progress | 原始名称、比例、细进度条；不擅自改成“完成率” |
| chart | 柱图比较、折线趋势、环形比例分别有类别/数据标注；fixture 明示，不生成无依据趋势 |
| image | 原比例内容图与图注，支持大图查看 |
| diagram | 浅底节点与细箭头，保留可展开的图表源文本；此处为固定视觉示例，无解析器 |
| callout | 说明、通过、警告、失败四种语义，使用图标和标题而非只有底色 |
| divider | 仅用细线与间距结束一段内容，不再包一层容器 |

另提供四种内容组合布局示意，供 DSH 理解块之间的空间关系。它们属于组件评审页，不成为成果页的四套新导航。

## 8. 交互与响应式

原型支持场景切换、桌面/390px 评审宽度、文件阅读、版本选择、需求对照、原文切换及下载、图片放大、代码逐文件展开、关闭风险展开、图表源文本展开、回到顶部、摘要复制及查看首页参考。

所有可操作元素有可见焦点样式；文档与图片使用原生 dialog，可通过 Escape 关闭。减少动态效果偏好会取消过渡。不能用颜色替代可读状态。

在 1300px、900px、620px 逐步减少外侧空间和列数。390px 实际截图使用 390 × 844 浏览器视口，不是把桌面截图缩小：文件集合、检查、时间线和组件均转为单列；文档全屏；代码与表格保留局部横向阅读。

桌面报告的旁注在移动端收起，其关键引用与依据仍保留在正文。顶部 390px 按钮是快速布局预览，不等同于模拟整台手机；实际移动截图以真实视口为准。

## 9. 相较当前版本的实质变化

| 现有表现问题 | 本轮设计变化 |
| --- | --- |
| 摘要与其他字段权重相近 | 以本轮变化句作为首屏主标题，名称退为题签 |
| 文件只是一组相似条目 | 文件集合有主次关系、纸张身份、预览与阅读入口 |
| 数值、目标、状态近似同构 | 六种 Metrics 按阅读任务分别组织 |
| 单页仍有字段排列感 | 交付简报和专业文章使用两套内容节奏 |
| 发布、验证、风险容易混读 | 首屏审阅旁注 + 证据分布 + 逐条检查 + 独立风险 |
| 版本缺少演进关系 | 时间轴连接变化、历史原文与版本对照 |
| 技术内容容易变成普通文本 | API、环境、文件与 diff 各有专业结构 |
| Custom 像类型清单 | 正文、表格、图形使用共享阅读网格并可跨栏 |

## 10. DSH 视觉实现交接

1. 以 HTML 的真实空间比例、截图及本说明共同作为设计依据；不要只抽取颜色与圆角后恢复等权卡片。
2. 保留“本轮变化 / 交付物 / 审阅结论”三者的首屏层级。强调文件的选择不能凭索引推断业务优先级。
3. 标题、正文、标注三级尺寸必须保留。长文正文不低于本设计的 15px，版本和时间不能抢过文档名。
4. 不把原型的 fixture 场景选择器或规格英文标签带入正式阅读流程；来源提示应按产品真实数据来源保留。
5. 状态展示不得改变数据含义：ready 不是 verified，旧版 pass 不是当前通过，任务进度不是测试通过率。
6. 文件版本、检查引用版本、历史节点必须在视觉上关联；切换旧文档时保留历史提示。
7. 保留表格、代码的局部滚动和等宽排版，不用缩小字号解决宽度。
8. 单列响应式通过重排与自然换行实现；不要整体缩放桌面视图。
9. 操作按钮要有悬停、键盘焦点与触摸可达区域。移动端的关闭与版本切换必须始终易于找到。
10. 本轮未设计通用渲染逻辑或协议扩展。生产接入由后续开发负责；本 HTML 的静态场景组织方式不应直接当作业务架构。
