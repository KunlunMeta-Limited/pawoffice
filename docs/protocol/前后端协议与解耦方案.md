# AI Office 前后端协议与解耦方案

> 审查日期：2026-09-20  
> 参考基线：`D:/workSpace/KunlunMeta_Git/master-plan.md`  
> 分析范围：`ai-office-react-main`、`openpaw/crates/openpaw-engine-host`  
> 文档性质：现状审计与目标方案，不代表协议已经实现。

## 1. 执行结论

当前系统不是“前端直接耦合 Rust Host”，而是“浏览器只连接 Gateway，但 Gateway 与 Host 私有协议、OpenPaw 私有存储和产品编排高度耦合”。网络拓扑方向基本正确，协议分层和职责边界不合格。

关键结论如下：

1. 浏览器不得直接连接 Rust Host。否则会暴露 Basic Auth、OpenCode 兼容细节、Provider 错误和内部并发语义，并绕过 Gateway 的文件边界、脱敏、CORS 与错误转换。
2. `master-plan.md` 只批准两条 AI Office 链路：Host 到 `/actions` 的动画投影，以及 Gateway 直接只读 `OPENPAW_HOME` 的五类摘要接口。当前完整对话、任务写入、文件/技能正文和通知仍是计划外扩展；Calendar/OCR 实现已于 2026-09-20 从核心 Gateway 删除。
3. 当前 Gateway 同时是 HTTP 入口、Host adapter、JSONL 解析器、文件仓储、任务执行器、通知存储和动画 broker。任何一层变化都可能迫使整文件联改。
4. 前端虽然没有直接请求 Host，但已经知道 `turnID`、`userMessageID`、Host 的 409/429、排队位置、终态 marker 和重放规则，属于“间接协议耦合”。
5. 要支持前后端独立开发，必须冻结一个正式的 `Office Application API v1`。浏览器只依赖该协议；Gateway 内部再通过 adapter 访问 Host、文件系统和动作队列。
6. `/actions` 是可丢弃的视觉投影，不是业务事实源。对话完成、任务完成和审批结果都不能通过人物动画判断。
7. 最小改动的第一步不是重写 Rust 或 React，而是先把 DTO、错误码、数据所有权和契约测试独立出来，再逐步替换 Gateway 内部实现。
8. Gateway 当前创建的 goal frontmatter 缺少 Rust `GoalFrontmatter` 要求的 `id/created/source/confidence` 等字段，ID 也不保证满足 `goal_<hex>`；继续由两套实现写同一目录有数据冲突风险。
9. Host 当前把工具直接映射到 `rosterNo=1..6`。最终目标应是 Host 只发 `tool.started/turn.finished` 等语义事件，由 Office 决定角色、文案和动画；迁移期可保留 `/actions` 兼容。

### 1.1 审核者必须先做的产品决策

| 选项 | 含义 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A. 严格回归 master-plan | AI Office 只保留五类只读摘要和动画；对话只显示摘要 | 改动最少、边界最清晰 | 删除当前完整对话、任务执行、日历、通知、OCR 等能力 | 若目标是最大程度还原基础版本，选此项 |
| B. 承认现有产品扩展 | 保留完整对话、审批、任务等，但升级 master-plan 并建立正式 Office API | 保留现有业务价值，可独立开发 | 必须完成协议化、模块拆分和契约测试 | 若这些功能要上线，推荐此项 |

在该决策确认前，不建议继续增加 Gateway 路由或让前端读取更多 Host 字段。

## 3. 当前边界与实际链路

### 3.1 master-plan 批准的边界

| 线路 | 方向 | 协议 | 用途 | 事实源 |
|---|---|---|---|---|
| A | OpenWork ⇄ Host | OpenCode v1 HTTP/SSE 子集 | 聊天、流式 part、审批、终止 | Host session/turn |
| B-1 | Host → Gateway → Pixi | HTTP JSON `POST/GET /actions` | 人物动作和状态投影 | 非事实源，可丢弃 |
| B-2 | Gateway → 文件系统 → Browser | HTTP JSON `GET /office/*` | 会话、技能、文件、任务、角色摘要 | 文件系统摘要 |

原计划明确规定：`/office/*` 只读、不写 `OPENPAW_HOME`、不依赖 Host 进程；对话面板只显示 session 摘要，不加载正文。

### 3.2 当前实际边界

`Browser :5173 → Gateway :8765 → Host :4096 → AgentLoop/Provider` 已经成为完整业务链路。Gateway 还直接访问：

- `<OPENPAW_HOME>/sessions/*.jsonl`：会话摘要兼容读取；
- `<OPENPAW_HOME>/skills/*/SKILL.md`：技能列表和正文；
- `<OPENPAW_HOME>/goals/*.md`：任务读取、创建、取消、重试和恢复；
- `OPENPAW_OFFICE_WORKSPACE`：文件树和正文；
- Gateway 进程内数组：通知，重启即丢失。

Calendar/OCR 的 Gateway 路由、前端 API 和类型已删除；Calendar 和 Browser 页面仅保留基线要求的静态“不支持”状态，不发相关请求。

## 4. 协议分层定义

目标系统必须把协议分成五层，禁止混用。

| 协议层 | 调用方 → 被调用方 | 职责 | 是否公开 | 所有者 |
|---|---|---|---|---|
| OpenCode Compatibility API v1 | OpenWork → Host | 兼容 SDK 的 session、message、SSE、permission | 对 OpenWork 稳定 | Rust Host |
| Office Application API v1 | Browser → Gateway | AI Office 业务 DTO、命令、查询、统一错误 | 对前端稳定 | AI Office 后端/Gateway |
| Host Adapter API | Gateway → Host | 执行会话、回合、审批、状态和恢复 | 仅进程间内部 | Gateway + Host 联合维护 |
| Office Action Projection | Host → Gateway → Browser/Pixi | 尽力人物动画、状态投影 | 可版本化兼容 | 场景/动画模块 |
| Storage Provider Ports | Gateway → repositories | session/task/skill/workspace 的读写抽象 | 不走网络也必须有接口 | Gateway 后端 |

### 4.1 不可跨越的规则

1. React 只导入 Office API DTO/client，不导入 Gateway 或 Rust 代码。
2. React 不处理 Host 原始状态码，不认识 JSONL 事件名，不读取环境变量和绝对文件路径。
3. Gateway controller 不直接调用 `fs`；必须通过 repository/provider。
4. JSONL、goal frontmatter 和 SKILL.md 是存储格式，不是前后端协议。
5. Host 的 `request_admission`、`turn_accept_v1`、`turn_finish_prepare_v1`、`turn_finish_commit_v1` 是内部恢复日志，禁止透传给浏览器。
6. 动画失败不得改变回合结果；动画状态不得用于判断任务或回合是否完成。

#### 5.2.1 OpenCode SSE 事件

| 事件 | 控制内容 | 恢复语义 | Office 是否应直接消费 |
|---|---|---|---|
| `session.created` / `session.updated` | 会话创建、标题/时间更新 | 断线后重新 GET session | 否，由 Host adapter 转换 |
| `session.status` | busy/idle 实时状态 | 不代表持久终态 | 否 |
| `session.idle` | 当前活动回合退出 | 仍需 turns/message 对账 | 否 |
| `message.updated` | user/assistant 消息元数据 | 历史由 GET message 恢复 | 否 |
| `message.part.updated` | text/reasoning/tool part 快照 | 历史由 GET message 恢复 | 否 |
| `message.part.delta` | 流式文本增量 | 断线增量不重放 | 否；Office 当前也未使用 SSE |
| `todo.updated` | todo 摘要变化 | 可重新查询/读取 | 否 |
| `permission.asked` / `permission.replied` | 审批创建和消费 | 以 GET permission 为准 | 否，由 ApprovalPort 转换 |
| `stream.gap` | broadcast 落后或漏事件 | 必须重查 status、turns、message | 否，属于 Host 恢复信号 |

SSE 只发送建立连接后的新事件，不是事件存储。内部 JSONL 事务事件 `request_admission`、`turn_accept_v1`、`turn_finish_prepare_v1`、`turn_finish_commit_v1`，以及 scheduler ticket、锁和取消令牌，均不得进入 Office 协议。

Host 可选 Basic Authentication 只用于服务间连接。工作区选择规则和绝对 `directory` 是 Host/OpenCode 兼容细节，Office 对外应只使用受控 `workspaceId`。

### 5.3 Host → Gateway → Pixi：动作协议

动作请求：

```json
{ "type": "set_state", "rosterNo": 1, "state": "thinking", "task": "处理当前回合" }
```

```json
{ "type": "desk_visit", "visitor": 1, "host": 3, "message": "读取工作区文件" }
```

当前可靠读取扩展：

```json
{
  "actions": [{ "type": "set_state", "rosterNo": 3, "state": "working", "task": "读取文件" }],
  "nextCursor": 108,
  "oldestCursor": 41,
  "gap": false,
  "reset": false
}
```

规则：Host 单次 POST 超时 500ms、不重试；失败不影响 Agent 回合。Gateway journal 有界，游标过旧可能 `gap=true`，前端应重建人物投影，不能补推业务事实。

#### 5.3.1 当前动作控制映射

| 引擎时机/工具 | 当前角色 | 动作 | 控制的 UI 功能 |
|---|---|---|---|
| turn 开始 | 1 王明 | `set_state(thinking)` | 主角色思考动画和任务短文案 |
| `web_search/web_fetch/web_extract` | 2 李研 | 首次可发 `desk_visit(1→2)`，再设 working | 网络/检索角色动画 |
| `read_file/grep/glob` | 3 周理 | 首次可发 `desk_visit(1→3)`，再设 working | 文件读取角色动画 |
| `write_file/edit_file/notebook_edit` | 4 陈书 | 首次可发 `desk_visit(1→4)`，再设 working | 文件写入角色动画 |
| 正常或失败回合结束 | 5 刘市 | 短暂 working 后 idle | “整理回合结果”动画 |
| SuggestConfirm 审批等待 | 6 赵审 | `set_state(working)` | 审批等待提示 |
| abort/回合结束 | 本回合占用角色 | `set_state(idle)` | 清理人物状态；取消时不做整理动作 |

同一回合最多一次 `desk_visit`；多 session 通过 owner 集合避免一个回合结束时把另一个仍在工作的角色置为 idle。该映射属于当前实现，不应继续作为 Rust 领域规则扩展。

## 6. 建议的 Office Application API v1

建议统一挂载到 `/api/office/v1`。迁移期保留旧 `/office/*` adapter，不要求一次改完 UI。

### 6.1 统一响应和错误

查询成功直接返回 DTO；命令成功返回命令接收对象：

```json
{
  "commandId": "cmd_01...",
  "requestId": "client-generated-id",
  "resourceId": "session_123",
  "operationId": "turn_456",
  "state": "accepted"
}
```

统一错误：

```json
{
  "error": {
    "code": "session_busy",
    "message": "该会话已有活动回合",
    "retryable": true,
    "traceId": "req_01..."
  }
}
```

前端必须按 `error.code` 分支，不按 409/429 猜业务含义。HTTP 状态仍保留标准语义，但只是传输层信息。

### 6.2 建议路由

| 方法与路径 | 作用 | 幂等/并发 | 后端端口 |
|---|---|---|---|
| `GET /api/office/v1/sessions` | 会话摘要 | 只读，可缓存 2s | SessionQueryPort |
| `POST /api/office/v1/sessions` | 创建会话 | `Idempotency-Key` | ConversationCommandPort |
| `DELETE /api/office/v1/sessions/:id` | 删除会话 | 活动时拒绝 | ConversationCommandPort |
| `GET /api/office/v1/sessions/:id/messages` | 可展示正文 | 只读、字段白名单 | ConversationQueryPort |
| `POST /api/office/v1/sessions/:id/turns` | 创建异步回合 | 幂等键；同 session 单活动回合 | TurnCommandPort |
| `GET /api/office/v1/sessions/:id/turns/:turnId` | 回合状态/终态 | Host 事实投影 | TurnQueryPort |
| `POST /api/office/v1/sessions/:id/turns/:turnId/cancel` | 请求取消 | 重复取消安全 | TurnCommandPort |
| `GET /api/office/v1/approvals` | 待审批列表 | 只读 | ApprovalPort |

### 6.3 数据例子

创建会话：

```http
POST /api/office/v1/sessions
```

## 7. 当前完整链路说明

### 7.1 会话创建

1. UI 生成 `requestID`，调用 `POST /office/conversations`。
2. Gateway 校验字段并代理 OpenCode `POST /session`；若带首条消息，再调用 `prompt_async`。
3. 创建请求按 `requestID` 缓存十分钟，用于成功结果重放和并发合并。
4. 创建 Promise 失败时立即删除缓存项；Host 恢复后同一 `requestID` 可以重新执行，不能永久重放旧失败。
5. 首条 prompt 失败时删除刚创建的 session，避免残留不可用空会话。

### 7.2 异步回合、排队和完成

1. UI 调用 `POST /office/conversations/:id/messages`，正文包含稳定 `requestID`。
2. Gateway 把该请求转换为 Host `POST /session/:id/prompt_async`；Host 在持久化 admission 后返回 204 和 `OpenPaw-Turn-ID`。
3. Host 校验同 session 的活动回合和幂等指纹，再进入默认 `4 running + 32 FIFO queued` 的全局调度器。
4. 前端当前仍通过 `useConversationController` 轮询 Gateway 的批量/单会话 status 和 messages；`ConversationService`、`HostClient`、`/api/office/v1` 是第 6 章目标架构，尚未实现。
5. Gateway 合并三类 Host 事实：status 表示活动态，turns 表示持久终态，message 表示可展示正文。
6. status 中消失不能直接判定成功；只有持久 turn outcome 或明确终态才可解锁输入。

#### 7.2.1 终态与正文投影延迟

1. Gateway 首次读取 messages 和 turns。
2. 仅当 turn 已是 `completed`、但关联 assistant 正文尚不可见时，按 50ms、100ms、200ms 有界重读。
3. `failed/cancelled` 不进入该等待窗口，避免掩盖真实失败。
4. 重读后仍无正文才生成持久可见的 `completed_without_reply` 错误投影。
5. turns 暂时不可用时仍返回已经读取到的普通消息，不把单路故障扩大为全部正文不可见。

#### 7.2.2 并发与幂等矩阵

| 场景 | 当前行为 |
|---|---|
| 同 session、相同 `requestID`、相同正文 | 重放原 turn/确认，不重复执行 |
| 同 session、相同 `requestID`、不同正文 | `409 idempotency_conflict` |
| 同 session、不同 `requestID`、已有活动回合 | `409 active_turn` |
| 不同 session | 进入全局调度器，可并行或排队 |
| 默认容量 | 4 running + 32 FIFO queued |
| 第 37 个同时 admission | `429 queue_full` |
| 前端收到 `active_turn` | 只在身份可确认时接管已有 turn |
| 前端收到 `idempotency_conflict` | 显示失败，不接管其它 turn |

### 7.3 取消

1. UI 提交目标 `turnId` 的取消命令。
2. Gateway 验证该 turn 是否仍属于 session 的活动回合。
3. Host abort 同时取消 AgentLoop、唤醒审批等待、清理角色动作。
4. HTTP 成功只表示取消请求已受理；UI 继续查询直到 `cancelled/failed/completed` 终态。

### 7.4 审批

1. Host 产生 pending approval，并暂停该工具路径。
2. Gateway 查询并白名单转换，不透传工具输入和敏感路径。
3. UI 提交决定；同一 approval 只允许消费一次。
4. abort 与 reply 竞争时由 Host 生命周期锁决定唯一结果。

### 7.5 动画

1. Host 从 AgentEvent 映射出人物动作。
2. Host 最多等待 Gateway 500ms，不重试。
3. Gateway 写入有界 journal 并更新人物投影。
4. Pixi 使用游标轮询；发生 gap 时重置场景状态。
5. 整条链路不参与回合事务，不承担重放或完成证明。

### 7.6 故障与恢复分支

| 故障 | 收敛行为 |
|---|---|
| Provider 截断、空响应、缺少正式终止证据 | 记录类型化失败，不伪造 `completed` |
| Provider 429/503/529 或流内不可用 | 保留结构化错误和 `retryable`，失败上下文回滚到回合前 checkpoint |
| Host 已接收但 ACK 丢失 | 使用同一 `requestID` 重试并重放原 turn |
| 创建 session 明确失败 | 删除 Gateway 创建缓存项，允许同键恢复重试 |
| terminal 先于 assistant 正文可见 | 50/100/200ms 快速重读；完成后 5 秒宽限内不插入临时失败，宽限外仍缺正文才报告不完整响应 |
| Gateway/Host 明确拒绝入场 | 在目标会话追加可见失败消息并解除 pending |
| HTTP 超时、是否入场不确定 | 继续按 requestID/turnID 监视，不立即重复提交或判失败 |
| 页面或会话切换 | 每个 session 的 monitor 独立运行，不能由当前选中项取消 |
| 动画 Gateway 不可用 | 只丢失视觉投影，不改变 Agent 回合结果 |

### 7.7 模型服务超时专项审计

网页显示“模型服务响应超时，本轮未完成，请稍后重试”时，不能直接推断浏览器等待了 120 秒或前端主动终止了模型。当前系统存在五个不同超时边界：

| 边界 | 当前值 | 判断位置 | 到期行为 | 是否终止已运行的模型回合 |
|---|---:|---|---|---|
| Browser → Gateway 请求确认 | 12 秒 | `officeGatewayApi.fetchWithTimeout` | 中止本次 HTTP 等待；发送命令使用同一 `requestID` 重试一次 | 通常否；只代表 ACK 不确定 |
| Gateway → Host 接收确认 | 5 秒 | `action-gateway.promptOfficeConversation` | 中止 `prompt_async` HTTP 等待；带幂等键时重试一次 | 通常否；Host 可能已接收并异步执行 |
| 前端回合监视 | 120 秒 | `useConversationController.monitorConversation` | UI 切为 `timeout/正在核对本轮状态`，继续轮询 | 否 |
| Provider TCP 建连 | 15 秒 | `openpaw-llm/http.rs::stream_client` | 返回 Provider 连接错误 | 是，本次 Provider 尝试失败 |
| AgentLoop 建流/逐帧空闲 | 120 秒 | `agent_loop.rs::stream_with_retry` | 建流无结果或下一帧长期不来时返回 `Error::Timeout` | 是，本次尝试失败；是否重试取决于输出状态 |

当前失败路线如下：

```text
Provider HTTP/SSE 超时、断流、连接重置或读取错误
  -> AgentLoop classify_api_error / Error::Timeout
  -> 无正文输出时按预算重试；已有 TextDelta 时不重放
  -> Host classify_turn_error
  -> failed turn outcome，code=provider_timeout
  -> Host 恢复回合前 session checkpoint
  -> Gateway 丢弃 Host 详细 message，只按 code 映射固定中文
  -> Browser 轮询 messages + turns，显示 system error marker
```

`provider_timeout` 当前混合了两类根因：一类是真正的建流/逐帧等待超时；另一类是 `connection/reset/eof/network/error sending request/stream read/response decode` 等被归为 `RetryableTransient` 的连接故障。Gateway 再把两类统一显示成“响应超时”，因此 UI 文案不能用于定位根因。

2026-09-20 真实样本 `turnID=4_b24b867fb0e248d0aea5e50c71198933` 从 14:07:30 到 14:09:12，共 102.063 秒，持久终态为 `provider_timeout`，Host 内部消息是“模型服务连接暂时不稳定”。该时长小于单次 120 秒 AgentLoop 定时器，且命中了 `Provider/Other -> RetryableTransient` 分支，因此可排除前端 120 秒截断和本地单次 frame timeout；原始 tracing 未落盘，无法继续区分 `http send`、`stream read` 或连接重置。

失败后 Host 把内存 session 恢复到整轮前 checkpoint，只提交 failed outcome。外部工具已经产生的文件或系统副作用无法随 checkpoint 回滚，这是当前最重要的恢复风险。AI Office 又没有消费 Host `/event` SSE，只轮询成功提交后的 message/turn，因此即使 Host 曾经发出部分增量，网页也不会稳定保留。

## 11. 剥离实施阶段

### Phase 0：冻结与决策，P0

- 冻结新增路由和新增 Host 字段透传。
- 由审核者选择严格回归 A 或正式扩展 B。
- 把本文中的现状路由导出为 OpenAPI/JSON Schema，并建立协议版本号。
- 明确 Host、Task、Workspace、Action 各自事实所有者。

验收：仅根据 schema 和 mock server，前端可以编译并完成主要交互；后端可独立跑 contract tests。

### Phase 1：抽离契约，P0

- 新建 `contracts/office-api-v1`，存放 OpenAPI、JSON Schema、错误码。
- 生成 TypeScript client/DTO；Rust 不共享源码类型，只用协议夹具验证。
- 把 Host 原始错误映射为稳定 Office error code。
- 拆分 `VITE_OFFICE_API_URL` 和 `VITE_OFFICE_ACTIONS_URL`。

验收：React 中不再出现 `OpenPaw-Turn-ID`、Host Basic Auth、JSONL 类型和基于裸 409/429 的业务判断。

### Phase 2：拆 Gateway 单体，P0/P1

建议目录：

```text
gateway/
  http/controllers/
  application/conversation-service.mjs
  application/task-service.mjs
  adapters/host/openpaw-host-client.mjs
  adapters/storage/session-repository.mjs
  adapters/storage/task-repository.mjs
  adapters/storage/skill-repository.mjs
  adapters/storage/workspace-repository.mjs
  adapters/actions/action-broker.mjs
  adapters/ocr/ocr-client.mjs
  contracts/
```

controller 只做 HTTP 解析、校验和响应映射；应用服务负责编排；adapter 负责外部格式。

### Phase 3：停止直接理解 Host 私有存储，P1

- session 摘要从 Host API 或独立索引读取，不再由通用 controller 解析 JSONL。
- goal Markdown 只由 TaskRepository 读写；后续可更换 SQLite/Host API。
- 文件和技能路径守卫集中到 repository，所有入口复用同一安全策略。
- 内部 HostClient 可以先继续调用 OpenCode 路由；稳定后再评估 `/internal/office/v1`，避免过早重写 Host。
- 最终隔离目标下，Gateway 不再直接访问 `OPENPAW_HOME`；过渡期的只读文件 adapter 仅为控制改动范围，不能被定义成长期协议。
- Host 逐步停止感知 Office 名册和 Gateway URL，改为发布带 `schemaVersion/eventId/sequence/sessionId/turnId/type` 的语义事件；Office projection 再生成动画动作。

### Phase 4：前后端独立开发，P1

- 前端开发只启动 Office API mock，不要求 OpenPaw/Provider。
- Gateway 开发使用 Host fake server 和文件系统 fixture。
- Host 开发只运行 OpenCode/Host adapter 合同，不启动 React。
- 联调只验证版本化协议和端到端关键旅程。

## 12. 版本、兼容与错误策略

1. URL 主版本：`/api/office/v1`。新增可选字段不升主版本；删除、改名、语义变化升 `v2`。
2. 请求幂等：写命令使用 `Idempotency-Key`；迁移期 adapter 映射到 Host `requestID`。
3. 超时：客户端超时只代表“未收到确认”，不得自动认为命令失败；同幂等键可安全重试。
4. 重试：只对网络失败、明确 `retryable=true` 或 502/503/504 重试；校验失败、冲突且不可重放时不重试。
5. 兼容窗口：旧 `/office/*` 与新 API 并存一个发布周期，日志统计旧路由调用，归零后删除。
6. 错误码最小集合：`invalid_request`、`not_found`、`session_busy`、`idempotency_conflict`、`capacity_exhausted`、`dependency_unavailable`、`forbidden_path`、`payload_too_large`、`operation_not_cancellable`、`internal_error`。

### 14.1 三类专家审查共识

| 视角 | 共识 | 特别提醒 |
|---|---|---|
| 框架分析 | 允许依赖方向应是 React → Office Contract → Gateway → OpenPaw Integration Contract | 完全隔离的最终状态不能继续共享磁盘；当前 B-2 只读直扫只能作为过渡方案 |
| Rust/Host | OpenCode Compat、Office Engine、Office Action 必须是三套协议；内部事务事件保持私有 | 保留 admission、幂等、恢复等可靠性实现，不要为了还原而删除正确的运行时机制 |
| TypeScript/Gateway | 先用 Port/Adapter 收口最稳妥；React Hook 不应承担跨接口终态算法 | permission 必须白名单转换，directory 改为 workspaceId，API URL 与动作 URL 分离 |

专家意见的短期差异只在“何时停止 B-2 共享磁盘”：最小改动方案先把直读封装进只读 adapter；完全隔离方案再将它替换为 OpenPaw 查询协议。两步并不冲突。

## 15. 推荐审核结论

若当前目标是“尽可能还原、最小改动”，建议批准以下组合：

1. 立即保留 master-plan 的五类只读摘要和动作协议。
2. 保留 cursor/journal 这一可靠性增强，但不把它升级为业务事件总线。
3. 优先回退或禁用 calendar、notifications、OCR、workspace 绝对路径暴露。
4. 对任务写入/执行单独评审；未明确产品必要性前回到只读。
5. 完整对话暂不直接删除，先冻结为可选 feature；若确认保留，必须先完成 Office API v1、后端 turn projection 和 contract tests。
6. 不让浏览器直连 Rust Host，不把 OpenCode wire types 作为 Office 前端协议。

这一路径能先减少计划外能力和高风险写入，同时避免直接回滚可靠性修复造成重复执行、错误解锁或无法恢复。
