# 成果看板前端改版 · ChatGPT 设计交接包

这个包用于把「成果阅读页」改版的全部上下文交给 ChatGPT 网页端做方案设计。

## 怎么用（三步）

1. 打开 ChatGPT，**上传**以下文件：
   - `ALL-IN-ONE.md`（单文件合并版：任务书 + 需求 + 关键源码）
   - `screenshots/current/` 里的 4–6 张关键截图（overview、deliverables、mobile、office 入口）
   - 可选：`screenshots/prototype/` 的 5 张（上一版未落地探索，用来说明"为什么先否掉了气泡方案"）
2. 先发送上面的**提示词**（见下方「提示词」一节）。
3. 等它按 12 节输出方案。若篇幅被截断，回复"继续第 N 节"。

> 如果上传附件失败，直接粘贴 `ALL-IN-ONE.md` 全文也可以（约 100KB，可能需要分两条发）。
> **不要**上传整个仓库或 `node_modules`。

## 提示词（复制这段发送）

```text
你是一位资深 B 端产品设计师 + 前端信息架构师。附件是一个 AI 办公室产品的「成果阅读页」现状材料：
一份设计任务书（02-design-brief.md）、需求原话（03-requirements.md）、关键源码，以及若干现状截图。

请先读完材料，然后严格按任务书第 8 节要求的 12 个小节输出一份完整设计方案（Markdown）。
硬性约束，违反任何一条方案即作废：
1) 不改数据协议（字段集合/枚举值不可增删），只从前端解决；
2) 不引入新依赖，图标只能用 lucide-react；
3) 不允许出现 Tab / 分段控件 / 按分类切分的顶部导航——必须是一个页面集成全部成果；
4) 现有 9 项能力（历史交付、文件预览与版本对比、复制摘要、下载报告、导出原始数据、检查/风险/任务/版本/决策渲染、任务详情、模态交互与焦点恢复、屏幕阅读器播报）一项都不能丢；
5) 必须先解决信息层级，再谈配色；
6) 场景内成果状态概览要用现有字段拼出来，并回答用户的质疑："专门搞个气泡显示成果是不是有点奇怪？"

输出要求：用 ASCII 画线框（桌面 ≥1280 与窄屏 <768 两版）；状态矩阵用表格；组件树的 props 必须对应材料里的真实字段名；不要输出可运行代码。
如果某处信息不足，列进"开放问题"，不要自己编造字段。
```

## 注意

- 材料里的行号对应 `code/` 下的副本，可能与仓库当前版本有轻微偏移。
- 上一版原型（`screenshots/prototype/`）**没有定稿**，不要让 ChatGPT 默认沿用。
- 本包里没有任何真实用户数据，演示数据来自 `resultDemo.ts`。
