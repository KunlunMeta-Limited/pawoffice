# 成果空间 · 前端设计交接

分支：`codex/result-board-design`。基于 main `b69f24f`。

本次交付是可运行的 React 设计组件与独立交互预览，没有修改正式办公室入口、协议、服务端或现有成果逻辑。示例数据和文件只用于设计演示。

## 查看设计

根目录运行 `npx vite --host 127.0.0.1 --port 5178`，打开 <http://127.0.0.1:5178/result-design.html>。加 `?detail` 可直接打开文件成果详情。

右上角选择有交付物、事实描述、正在处理、暂无成果。该选择器仅用于设计预览。点击电脑气泡 → 详情 → 文件预览。支持遮罩及 Escape 关闭、焦点恢复、折叠依据、下载样例文件及移动端排版。

## 已确定的设计

- 暖白底、低饱和绿色、细边框，复用办公室素材。绿色结论区承载主要结果，状态标签独立表达待验收或已验证。
- 后排现有电脑是团队成果入口。气泡两行摘要，不展示复杂指标、任务列表或多个按钮。
- 详情取消三个主 Tab。顺序：结论、文件、指标、事实或说明、验证及执行记录。无内容的区域不显示。
- 桌面右侧轻量交付信息栏，窄屏移至正文后。
- 文件采用完整可点击行，不重复展示主要文件和全部文件。事实成果直接展示正文，不渲染空文件区。
- 依据与执行记录默认折叠；attention 提示在折叠区外显示。
- 进行中及暂无成果气泡不可打开空成果页，任务查看继续由现有入口承载。

办公室背景和四个工位用于设计示意。正式页面的气泡挂在后排现有电脑上，中间过道保留原样。

## Sol 接入任务

1. 将 ResultDetail 的版式用于 ResultWorkspace，保留 ResultDeliveryShell 的当前成果和历史快照语义。使用现有 reader 生命周期，不额外嵌套 DesignDialog。
2. 状态使用 resultPresentation。负责人、时间、执行状态均换为真实数据，时间沿用现有格式化方法。未知历史状态不能显示已完成。
3. summary、verdict 对应摘要和结论；空值或重复时只展示有意义的一份。不能从任务完成推导已验证。
4. 文件映射 artifacts；点击通过 ArtifactPreviewContext 打开 ResultArtifactPreview。DesignFilePreview 仅为示意，不能取代已有格式识别、校验、历史版本和下载功能。
5. 分析、事实、指标继续使用 resultContentLayout、ResultSectionCard 等结构化渲染器，置于设计容器内。不要转成字符串而丢失表格、图表、文件和证据关联。
6. 保留检查、风险、任务、版本、补充内容、复制摘要和报告导出。重要问题在折叠区域外提示。
7. OfficeCanvas 接入 ResultBubble，读取 currentBoard，点击复用 openWhiteboard。空态判断不能仅看 artifacts 数量，也不能只凭标题认定已有成果。
8. 复用后排现有工位的显示器锚点。后排有多个工位时取最右侧的工位。布局编辑时隐藏气泡。
9. 修复 ChatDeliveries 对纯摘要或结论交付的过滤和“0 项产物”文案。沿用会话隔离、历史快照和阅读中实时更新保持机制。
10. 不改协议和服务端，不新增依赖，不重写资源层。场景选择器、样例下载、预览品牌壳不进入正式产品。
