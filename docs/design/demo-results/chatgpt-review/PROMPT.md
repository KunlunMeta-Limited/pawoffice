# ChatGPT 审核提示词（演示成果阅读页）

你是 PawOffice「成果阅读页」的评审。请基于本包材料，审核 8 个演示任务完成后的成果页面是否**语义合理、信息层级清楚、视觉统一、诚实可信**。

## 材料

- `README.md`：场景→成果映射、复现方式、范围与已知边界
- `screenshots/01…08-*.png`：8 个场景成果页首屏（1440×900，真实前端组件渲染）
- `data/<scenario-id>.json`：8 份成果数据（经协议 schema 解析后的 JSON）
- `code/demoScenarios.ts`：演示任务定义（每场景 3 步、角色）
- `code/demoReports.ts`：每场景的聊天报告内容（指标/图表/发现/下一步）
- `code/demoResults.ts`：任务完成后生成成果的映射逻辑

## 审核维度（每个场景都要给结论）

1. **语义匹配**：成果标题/摘要/结论是否准确对应该演示任务？有没有把执行过程写成成果、或夸大结论？
2. **信息层级**：首屏能否在 5 秒内看到「结论 → 验收意见 → 交付物 → 验证状态」？信息量是否过密或过空？
3. **指标与交付物形态**：数值型/状态型/文本型指标是否用对形态？交付物（报告/数据表）是否与任务语义一致、可行动？
4. **诚实性与边界**：待处理检查、开放风险、模拟数据声明、结论边界（如「不能证明因果」「凭证补齐前不提交」）是否表达清楚？有没有把演示当成已验证成果？
5. **一致性与可读性**：8 个页面是否像同一产品？中文字排、术语（如「验收意见」「本轮交付」「验证与验收」）是否统一？长文本、表格、CSV 是否可读？
6. **可改进项**：区分 must-fix（阻断验收）与 should-fix（下一轮优化），并指出对应截图/JSON 字段。

## 输出格式

1. 一张 8 行×6 列的评分表（场景 × 维度，用 通过/需改进/不通过 + 一句话理由）
2. 问题清单：按严重度排序，每条包含「场景 / 截图 / 数据字段 / 问题 / 建议」
3. 总结：这一版能否作为演示成果页进入下一轮？还缺什么？
4. 明确区分「演示数据本身的限制」与「成果页设计/实现的问题」，不要把前者列为前端缺陷。

## 约束

- 不要假设存在真实后端或真实业务数据；所有内容均为本地模拟。
- 不要要求新增协议字段或改变数据结构（协议层已冻结），只评价展示与信息组织。
- 视觉评价请引用包内截图，不要凭空想象未展示的页面。
