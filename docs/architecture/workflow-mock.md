## 工程边界回归案例

需要专门检查回滚、移除、过期检查等边界时，改用 `-Scenario engineering` 启动，选择“全流程联调办公室”→“从对话到多轮交付”。

| 轮次 | 可以输入 | 应看到的结果 |
| --- | --- | --- |
| 1 | 确认目标 | 收到阶段总结，不显示空交付入口 |
| 2 | 生成首版文件 | 新增需求说明 v1 和接口 JSON v1；点击回复下“第 2 轮交付”查看。JSON 下载应仍为 JSON，不能加 Markdown 标题 |
| 3 | 更新需求并复核 | 需求 v2，新增报告，接口沿用 v1。特意保留 v1 的通过检查和后端 verified 状态，界面应显示“验证待核对”，不是已验证 |
| 4 | 回滚需求 | 当前采用需求 v1；打开第 3 轮的需求仍看到 v2，提示“当前采用版本 v1”，不声称 v1 是更新版本 |
| 5 | 移除接口文档 | 当前成果不再有接口；第 5 轮保留移除记录；第 2 轮接口仍能打开、下载 |
| 6 | 验收当前版本 | 针对当前采用版本完成检查，状态“已验证”；本轮保留所验证文件的引用，标记沿用 |

这里按轮次推进的是确定性演示脚本，不理解自然语言、不调用模型。六轮之后继续发送消息会重复当前版本验收。每个会话独立推进；可切换到“会话隔离测试”从第一轮重新体验，检查不串数据。

建议同时验证：刷新页面恢复聊天和交付；从第 2 轮打开旧版，看到 v1；下载原文件；第三轮查看新增/更新/沿用标记；当前集合和历史交付之间来回切换。实际版本内容、聊天历史均由此 mock 在内存保存。Ctrl+C 结束，重新启动会创建新演示办公室，不保留本次内存历史。

**聊天注册范围：** PawOffice 当前使用实例级的一个聊天地址。这个命令会把它指向 mock，因此运行期间只在本次演示办公室测试聊天；其他办公室的原聊天服务不会被 mock 处理。测试结束后，由原业务后端重新注册其 `chat.url`（或重新初始化原业务服务）。mock 不更改其他办公室的业务快照，不会替真实后端保存生产文件版本。

## 本次行为调整

- 白板标题为空仍保留有效成果和交付数据；错误的 Schema 仍会拒绝。
- 文档/附件通过显式 artifactId、可选 versionId 关联，取消运行时标题匹配。旧的无关联文档保留为说明文字；有效引用不再重复显示。
- 文件卡片与预览下载都按 MIME、版本名和原始内容下载；报告导出与全部轮次原始 JSON 导出使用不同文案。
- 后端 verified 与检查失败/过期/待补充冲突时，界面、聊天入口和导出报告显示验证待核对；不改写后端原始数据，不自行生成验收通过。
- artifact.change 可为 added/updated/removed/unchanged，显示交付变化摘要。字段省略的旧数据不推测变化。
- “当前采用版本”替代把当前集合一律称为最新版的提示；历史版本不会自动被当前版本替换。

## 自动验证

相关测试覆盖当前集合、聊天历史入口、指定版本下载、差异、回滚、移除、过期验证及空内容。运行命令见[测试目录](../../tests/README.md)。验证范围是模拟业务后端，真实后端的版本持久化仍按原分工由业务后端保障。

`node tests/browser/workflow.mjs` 使用独立临时 PawOffice 和同一套 mock 后端，在真实浏览器从空会话逐条发送六轮消息，验证交付、JSON 原件、更新、检查过期、旧版、回滚、移除、重新验收、刷新和第二会话。测试不会向用户现有的 8765 服务发送数据。
