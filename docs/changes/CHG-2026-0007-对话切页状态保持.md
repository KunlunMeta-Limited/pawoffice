# CHG-2026-0007：对话切页状态保持

## 先说结论

本变更修复新建会话发送后立即切到其它中心再返回时，当前会话、用户消息和等待状态消失的问题。会话摘要与选择状态上移到持续存在的右侧面板，消息正文和 pending 状态继续由既有会话视图缓存管理。它不改变 Gateway、OpenPaw Host、HTTP 字段或会话持久化格式。

## 2. 变更原因

旧实现把会话摘要和当前选择保存在 `SessionsPanel` 局部状态。导航切换会卸载该组件；当 Gateway 尚未刷新列表时，新会话无法重新选中，乐观用户消息和等待动画也不能与目标会话重新关联。若不修复，正常切页会被用户感知为会话丢失或发送失败。

## 9. 影响、数据流和实现

### 影响分析

影响仅限前端会话摘要、当前选择、消息视图缓存和布局。浏览器刷新后仍以 Gateway/Host 持久事实为准；标签关闭不会把临时摘要写入磁盘。异步返回仍必须携带目标 session，不能因当前选中会话变化而覆盖其它会话。

### 数据流和失败路径

```text
创建会话 -> OfficeRightPanel 保存摘要和 selectedSessionId
         -> SessionsPanel 展示并回调选择/删除
发送消息 -> conversationViewStore[sessionId] 保存消息和 pending
切换导航 -> SessionsPanel 卸载，但父级摘要和 store 保留
返回对话 -> 先恢复本地视图，再由 Gateway/Host 对账
```

Gateway 列表延迟或短暂失败时保留已知摘要；删除事件同步移除对应选择。浏览器刷新后本地临时状态可丢弃，但 Host 持久消息必须重新加载。

### 实现方案和选择理由

将会话列表和选择上移到 `OfficeRightPanel`，避免导航面板卸载销毁状态；沿用 `conversationViewStore` 保存消息运行态，避免重复建立第二份消息状态。没有写磁盘，因为 Host 才是会话事实源。
