# CHG-2026-0010：办公室对话消息脱敏与响应体优化

## 先说结论

本变更收敛 AI Office 专用消息接口，只允许消息元数据和 `text` part 进入浏览器，工具输入、输出、错误、reasoning 和未知字段均被过滤。OpenPaw Host 的 OpenCode 兼容消息接口保持完整，不受影响；前端缓存入口再做一次防御性清洗。该变更涉及 L4 Gateway，目录中没有真实安全批准和 PR 记录，因此保持评审中。

## 2. 变更原因

OpenPaw Host 的 `/session/:id/message` 是 OpenCode 兼容接口，必须保留工具输入、输出和推理 part。旧 Gateway 把完整响应原样转发到浏览器，使网页内存和缓存保留工具参数、抓取正文及潜在错误细节；大型工具结果还会在轮询中反复传输，导致第二轮响应变慢并扩大敏感数据暴露面。

## 9. 影响、数据流和实现

### 影响分析

Office UI 不再能从历史消息中读取工具和 reasoning 内容，工具名称与运行状态继续通过 status 和 `/actions` 摘要展示。用户和助手文本保持原文和顺序，不做无依据截断。浏览器传输体、内存和缓存占用下降；Host 兼容客户端继续读取完整原始路由。

### 数据流和失败路径

```text
Host /session/:id/message（完整 OpenCode parts）
  -> Gateway Office 专用路由（只保留 info + type=text part）
  -> officeGatewayApi.conversationMessages
  -> conversationViewStore（二次白名单清洗）
  -> 对话气泡
```

未知 part 或未知字段直接丢弃；单条坏消息不能把工具内容带入浏览器。Host 请求失败按既有 Gateway 错误映射返回，不在前端伪造正文。前端缓存即使收到旧 Gateway 或测试替身的完整对象，也只持久保留白名单字段。

### 实现方案和选择理由

过滤放在 Gateway 安全边界，避免敏感数据先进入浏览器再隐藏；前端缓存再做防御性清洗，覆盖版本错配和测试替身。没有修改 Host 原始接口，因为那是 OpenCode 兼容契约，收敛它会破坏其它客户端。
