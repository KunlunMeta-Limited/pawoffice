# CHG-2026-0005：对话、任务、技能与动画闭环

## 先说结论

本变更修复对话切页后丢失运行状态的问题，并让对话、任务、技能和办公室动画使用真实 Gateway/Host 数据形成可观察闭环。变更不修改 OpenPaw Core、Host 公共协议和默认移动端布局。后续多会话并发、失败终态和 UI 收敛由 CHG-2026-0011、0013 继续演进。

## 2. 变更原因

旧实现把对话面板局部状态当成回合状态来源，切换面板后可能丢失乐观消息和等待状态；任务、技能和人物动画也缺少统一的真实数据说明。用户无法判断对话是否仍在执行、任务是否绑定会话、人物动作是否只是视觉投影。

本变更建立浏览器会话视图缓存和真实 Gateway 数据展示，明确对话表示连续上下文、任务表示可追踪目标、技能表示可复用规范、人物表示同一 AgentLoop 的阶段投影。若不修改，切页会继续破坏对话体验，静态或推测状态也会误导用户。

## 9. 影响、数据流和实现

### 影响分析

组件卸载不再清除对话视图缓存；重新进入时先展示已有消息，再通过 Gateway 对账。任务通过 `sessionId` 链接执行对话，技能只表示执行规范，Office 人物动作仅表示运行阶段。浏览器缓存不成为 Host 的第二持久化写入者，不保存工具参数、工具结果、reasoning 或凭据。

### 数据流和失败路径

```text
用户消息 -> conversationViewStore（乐观气泡/活动回合）
         -> Gateway /office/conversations/:id/messages
         -> OpenPaw Host AgentLoop -> AgentEvent / session JSONL
         -> Gateway message/status -> 对话正文与状态
         -> /actions -> Dispatcher -> SceneBridge -> Pixi 人物投影
```

失败时前端保留目标会话状态并展示受控错误；切换面板不能取消 Host 回合。Office 动作失败不得改变 AgentLoop 结果。

### 实现方案和选择理由

采用按 sessionId 索引的模块级浏览器视图缓存，避免把运行态绑定到当前 React 面板实例。没有把状态写回 JSONL，也没有修改场景核心，因为 Host 仍是会话事实和终态的唯一写入者。后续全局并发、终态持久化和本地失败正文由 CHG-2026-0011/0013 补强。
