# CHG-2026-0013：对话可靠性与统一架构文档

## 先说结论

本变更统一记录 AI Office、Gateway 和 OpenPaw Host 的对话协议与数据链路，并修复会话摘要加载、失败正文、跨 session 生命周期、动作轮询恢复、首页任务卡和对话布局问题。Host 仍是 session 与 turn 事实源，Gateway 只做受控代理、脱敏合并和有界缓存，浏览器缓存只负责快速恢复视图。历史测试覆盖单元、浏览器、原生三端、并发和压力，但 OpenWork 联调、部分故障注入、旧版回滚和人工权限 UI 仍未完成，不能宣称整个 master-plan 或正式发布已验收。

## 2. 变更原因

旧 README 只描述 `/actions`，不能说明当前 Host/Gateway/React 数据链路；会话列表只在进入对话中心后读取且离开时清空；Gateway 顺序扫描完整 JSONL；失败终态没有正文；前端依赖 1.8 秒无 assistant 文本猜测失败；首页仍渲染任务卡；对话普通与隐藏办公室模式层级和字号不一致。动作轮询若遇到半开连接也可能长期挂起。

本变更建立旧 HTTP 兼容矩阵和统一总架构文档；Host session 摘要优先读取并配合有界缓存和空闲预取；failed/cancelled 终态合并为可恢复的 system 正文；删除猜测性失败；保持 A/B 会话并行独立；首页只保留智能体状态与快捷工具；普通和专注对话布局收敛；半开动作轮询超时后自动恢复。

## 9. 影响、数据流和实现

### 影响分析

Gateway 的 session 摘要来源、短 TTL 缓存、消息与 turn 合并和错误映射发生变化；浏览器增加模块级摘要缓存、预取、真实终态收敛和失败正文持久显示。Gateway 不成为 session JSONL 的第二写入者，system failure notice 只来自 Host 脱敏终态或发送前可诊断失败。首页预取不得阻塞首屏或提前启动权限轮询。

并发仍遵循不同 session 可并行、同 session 单活动回合。Host/Gateway 不可达时保留已有缓存和本地正文，并显示明确错误；迟到请求按 session 和 generation 隔离。动作轮询使用超时和下一轮恢复，不改变 FIFO 或角色状态事实。

### 数据流和失败路径

```text
应用空闲/导航 hover -> conversationSessionCache 预取
  -> GET /office/sessions -> Gateway 短 TTL/SWR
  -> Host GET /session（优先）
  -> Host 不可达时受控本地扫描（降级）

用户发送 -> Gateway POST message -> Host AgentLoop/Turn
  -> GET status（活动与 turnID）
  -> 并行 GET message + GET turns
  -> completed：展示 assistant text
  -> failed/cancelled：合并为脱敏 system 正文
  -> conversationViewStore[sessionId] -> 切页/刷新恢复

Host/Gateway 前置拒绝 -> 本地保留用户消息并追加受控失败正文
动作 GET 半开 -> Abort/超时 -> 下一轮轮询恢复，不重放已消费动作
```

### 实现方案和选择理由

Host 是唯一终态事实源，因此删除基于 1.8 秒无 assistant 的浏览器猜测。消息与 turns 并行读取，既保持 OpenCode 文本兼容，又能把失败/取消持久显示。摘要使用短 TTL 与 stale-while-refresh，切入先显示缓存再对账，在不延长启动关键路径的前提下降低约 1 秒等待。Gateway 只合并脱敏视图，不写 session JSONL，避免双写和恢复冲突。
