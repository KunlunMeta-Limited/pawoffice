## 2. 变更原因

现有代码已经具备不同 session 并行、同 session 单活动回合、失败 system 正文、基础切换恢复和场景 FIFO，但下表问题仍会造成错误解锁、假完成、刷新后状态丢失、长回复抖动、动画状态被破坏或测试假绿。每个阻断项都必须有代码修改、自动化证据和量化结果，不能只增加等待时间或修改测试预期。

| 编号 | 发布阻断项 | 当前实现证据 | 必须闭环的结果 |
| --- | --- | --- | --- |
| BLK-01 | 刷新只恢复当前选择会话 | `useConversationController` 只在选中 session 执行 `ensureConversationLoaded` | 启动或整页刷新后批量发现并恢复全部 queued/busy session，非当前会话显示运行态并禁止删除 |
| BLK-02 | `completed` 没有当轮 assistant 正文时静默成功 | `mergeOfficeConversationTurns` 可生成无正文 `completed` marker，控制器把它当终态 | `completed` 必须与目标 user 回合窗口中的非空 assistant 文本同时成立，否则生成可持久恢复的脱敏 system error |
| BLK-03 | 任务用旧回复误判当前回合成功 | `messageHasAssistantText` 扫描整个消息历史 | 任务成功只接受目标 `userMessageID` 到下一条 user 之前的 assistant 文本；缺少可证明关联时不得成功 |
| BLK-04 | Gateway 启动不主动恢复持久任务 | `schedulePersistedTaskRecovery` 仅由 `listTasks` 间接触发 | Gateway 监听成功后主动且幂等恢复 queued/in_progress；不依赖用户打开任务中心或调用 `GET /office/tasks` |
| BLK-05 | paused 被实现为 idle 并可能推进 FIFO | `OfficeActionConnector` 暂停时调用 `setAgentState(...idle...)`，`OfficeScene.setAgentState` 清除 mission | paused 是独立视觉控制状态；不得清 mission、角色业务状态、执行锁、完成计数或 FIFO，恢复后从原进度继续且只完成一次 |
| BLK-06 | 本地失败消息刷新后顺序错误 | `rememberConversationMessages` 使用 `[...remote, ...retainedLocal]` | 本地失败 user/system 对按稳定锚点回插原回合位置，后续成功回合始终排在其后，刷新前后顺序一致 |
| BLK-07 | 活动会话轮询请求量随 session 线性放大 | 每个 monitor 约每 250ms 读取 status 和 messages | 使用单一批量状态协调器和前后台分级正文读取，满足请求预算且不降低完成可见性 |
| BLK-08 | 同值状态仍发布并触发 React 更新 | `updateConversationView`、会话摘要 `publish` 无条件通知 | 语义相同的状态、消息和摘要不得更新时间戳、发布订阅或重新解析 Markdown |
| BLK-09 | 每次消息或状态变化都强制滚底 | `SessionsPanel` 对 `[messages, messageState]` 无条件设置 `scrollTop=scrollHeight` | 用户阅读历史时保持消息锚点；只有在原本接近底部、主动发送或首次选择时自动跟随新消息 |
| BLK-10 | 长助手回复已确认跨层损坏和丢失 | 50K 中文/emoji 经 Host 后出现 `U+FFFD`；180004 长度 assistant 在 Store 裁剪时被后置空 completed marker 整体淘汰 | OpenPaw UTF-8 修复后，50K 和 180K 跨 Host fixture、Gateway、Store、DOM、切换和刷新 SHA-256 一致；最新完整回合不得因预算丢失 |
| BLK-11 | 50K/180K Markdown 性能门禁当前失败/证据不足 | 50K 单样本 Store 到 DOM 约 122ms、刷新约 336ms、CLS 约 0.01236，但最长主线程任务约 686ms，超过 250ms 门槛；没有 10 次 P95 | 解析按消息内容缓存；修复正文保留后执行规定样本数，P95 和最长主线程任务全部满足量化阈值 |
| BLK-12 | 缺少 CLS、固定视口截图和 Canvas 像素证据 | 现有 E2E 主要验证可见性、尺寸和非空像素 | 固定视口保存截图工件，CLS、溢出、遮挡、Canvas 非空、活动变化和暂停冻结均有数值断言 |
| BLK-13 | 隐藏办公室与暂停语义没有正式冻结 | `officeHidden` 与 `officeScenePaused` 分属顶层状态，但没有完整状态机和回归矩阵 | 隐藏只改变布局和可见性，不停止会话、动作链路或篡改人物状态；暂停只冻结视觉执行，不等同隐藏或 idle |
| BLK-14 | Vitest 慢测和异步资源泄漏 | Gateway 生命周期用例在 Windows 上约 31 秒；默认 5 秒可超时，并出现异步错误泄漏 | 测试改为确定性时钟和显式资源回收；默认 `npm run test` 通过，重复运行无未处理错误且进程及时退出 |
| BLK-15 | abort 请求失败会错误解锁 | 取消请求失败后控制器可把 `pending` 设为 false 并停止 monitor | abort 只有在 Host 明确终态或后续对账确认无活动 turn 时才能解锁；网络/503 失败保留 pending 和 monitor，并显示可重试取消错误 |
| BLK-16 | 409 后不能接管 Host 已存在的活动 turn | 发送 409 只生成本地失败，控制器不知道 Host 当前 turn，后续可能重复 409 | 409 时立即读取目标 session status/turns，若存在 queued/running turn 则接管其 `turnID/userMessageID` 和 monitor；不得重复提交 Provider |
| BLK-17 | status 与 messages 分裂故障不能收敛 | status 持续 503 时，即使 messages/turns 已出现目标终态和正文，pending 仍可永久保持 | status、turns、messages 是可独立失败的数据源；任一来源不能单独伪造成功，但目标 turn 的持久终态加正文可收敛，分裂故障必须有有界退避和诊断 |
| BLK-18 | 迟到旧助手回复可能关闭新回合 | 当前恢复路径仍可能用上一轮 assistant 或无关联 completed marker 关闭新的 generation | 每个 monitor 固定绑定 `turnID + userMessageID + generation`；只接受目标 user 回合窗口内的正文和目标 turn 终态，旧 generation 的迟到结果只能更新其原回合 |
| BLK-19 | 同文失败消息会被错误去重 | 本地 system notice 可能按“角色 + 全文”去重，两个不同回合相同错误只保留一条 | 本地失败身份使用 `sessionId + localTurnOrdinal + messageKind`，同文不同回合必须分别保留，重复加载同一 envelope 才幂等 |
| BLK-20 | session 淘汰不是真实 LRU | 更新旧 session 的对象不会提升插入顺序，活跃或刚访问会话可能先被淘汰 | 读取、选择、写入、活动恢复均刷新显式 `lastAccessOrdinal`；活动、当前选择和含未同步本地失败的 session 禁止淘汰 |
| BLK-21 | 固定间隔刷新和同值 permissions 造成页面抖动 | 对话中心存在约 1.2 秒 agent/permission 定时刷新，权限新数组和同值 agent 状态仍触发 React 更新 | 活动时按需刷新、空闲退避；语义相同复用引用且不发布；进入首页/智能体/对话中心不得因定时器发生可见布局抽动 |
| BLK-22 | 同一候选 E2E 先 0/8、后隔离 8/8，页面装载与测试基础设施稳定性未闭环 | 2026-09-17 同一候选首次实跑 `npm run test:e2e` 为 0/8，多项 `page.goto('/')` 或 page fixture 在 30 秒超时，首例出现 `net::ERR_ABORTED`，移动端等待输入框超时；停止并行测试干扰后隔离复跑为 8/8。结果翻转证明页面装载、服务就绪探测、进程/端口回收或测试基础设施对并发负载敏感，单次绿测不能推翻首次失败 | 修复并发负载敏感根因；隔离 Gateway/Vite 下连续三轮完成 24/24，页面 shell、Canvas 和右栏不能阻塞 `load`，每轮无 `ERR_ABORTED`、fixture setup timeout、未处理异常、孤儿进程或残留监听端口；不得以串行特例、增加 timeout、减少断言或避开并发负载达标 |
| BLK-23 | 任务到对话的深链选择没有可靠落到目标会话 | 本次 E2E 点击“查看执行对话”后，“最近对话 2”没有 `aria-current="page"`，页面仍处于“正在读取消息” | 深链只消费一次并在目标会话已选中、已有缓存正文可见后完成；随后手动切换不被旧深链拉回，失败时显示可恢复的明确提示 |
| BLK-24 | 页面存在看似可用但实际不可交互或语义冲突的控件 | 侧栏“搜索功能、任务、员工…”是静态 `div`，同时展示 `⌘K`；“语音输入”显示为普通可点击按钮但只提示不支持；“全部暂停”和“全部继续”同时可用且没有当前状态语义 | 未实现能力必须禁用并标明“暂不支持”，或实现完整键盘/鼠标路径；搜索不可伪装成输入框；暂停与继续合并为单一状态控件或互斥禁用，并暴露 `aria-pressed`/状态文本 |
| BLK-25 | 紧凑样式牺牲可读性与点击安全 | 最终 CSS 将最近对话、权限、辅助状态和按钮压到 8px 至 10.5px，桌面对话删除按钮约 22×22px、发送按钮高约 27px | 正文和关键状态在 100%/200% 缩放下可读；所有目标至少满足 §10.1，删除、权限和暂停等高风险操作不得依赖小图标或密集相邻目标 |
| BLK-26 | 异步状态、权限和 Canvas 菜单缺少完整可访问语义与焦点管理 | 仅局部错误使用 `role="status"`；加载、排队、思考、完成和权限到达没有统一 live region/`aria-busy`；Canvas 人物菜单由指针打开，未见 dialog/menu 角色、初始焦点、焦点圈定或返回策略 | 纯键盘可完成所有核心旅程；动态状态被读屏器恰好播报一次；权限与人物菜单打开后焦点进入、Escape 关闭、关闭后返回触发点；Canvas 有等价的非视觉状态与操作入口 |
| BLK-27 | 不可逆和破坏性操作缺少误触保护与恢复设计 | 对话和日程删除按钮直接执行删除；对话删除目标在桌面仅约 22px，任务停止、权限拒绝和删除操作没有统一确认/撤销规则 | 活动项禁止删除；永久删除、拒绝和停止明确展示对象与后果，采用二次确认或可撤销策略；重复点击、双击、断网和响应丢失均幂等，不得删除错误对象 |
| BLK-28 | `App.css` 多轮尾部覆盖形成视觉规则冗余和回归风险 | 同一对话面板宽度、列表高度、按钮尺寸和字体在文件中被多组 CHG 规则重复覆盖，最终行为依赖源码顺序；不同断点存在 22/28/40px 等互相冲突值 | 收敛为单一 token/断点来源，删除失效覆盖；视觉值可由组件契约和快照定位，不再靠文件末尾“最终覆盖”；重构前后所有批准截图和量化指标一致或更优 |

当前强证据只证明部分既有路径：2026-09-16 的真实三端脚本通过 A/B 并行、同 session 409、队列晋升、长用户输入、取消、Host/Gateway 重启和浏览器切页；`npm run lint`、`npm run build` 通过。2026-09-17 的当前候选 E2E 在并行负载下先为 0/8，停止并行测试干扰后隔离复跑为 8/8；这只证明旅程在特定隔离条件下可以通过，同时证明页面和测试基础设施稳定性门禁尚未通过。首次运行还出现任务深链失败，后续单轮绿测不能替代根因修复和连续三轮证据。既有证据没有覆盖 BLK-01 至 BLK-28 的全部验收条件，不能作为本 CHG 已完成的依据。

## 9. 影响、数据流和实现

### 9.1 全活动会话恢复和轮询预算

```text
App 启动/整页刷新
  -> 预取 session 摘要
  -> GET /office/conversations/status（一次批量）
  -> 为每个 queued/busy session 创建或复用 generation
  -> 恢复运行圆点、删除保护和独立正文监视
  -> 当前 session 高频正文读取；后台活动 session 低频正文读取
  -> idle + 终态/正文对账完成后停止该 session 读取
```

修改要求：

1. 全应用只存在一个 status 调度器，不允许每个 session 各自每 250ms 请求 status。
2. 当前可见活动 session 的正文最多每 250ms 拉取一次；非当前活动 session 最多每 750ms 拉取一次；状态不变时不得发布 Store。
3. 浏览器 `document.visibilityState=hidden` 时 status 和正文降为最多每 1000ms 一次；恢复可见后立即对账一次。
4. 单 session 仍只允许一个活动回合；不同 session 的 generation、错误、工具摘要、队列位置和正文不得串写。
5. status 暂时失败时保留已知 pending，不得允许删除或新建同 session 回合；连续恢复后再清除错误提示。
6. abort 请求超时、断网或 503 时只记录取消请求失败，不得把 `pending` 置 false；monitor 继续对账，用户可以重试 abort。
7. 发送收到 409 时先接管 Host 已存在的目标 session 活动 turn；只有确认不存在可接管 turn 时，才保留本地冲突 notice。
8. status、turns、messages 分别维护健康度和退避。目标 `turnID/userMessageID` 的持久终态与正文已经可证明时，不因 status 单路持续 503 永久 pending。

### 9.2 completed 和任务成功的目标回合窗口

```text
terminal.userMessageID
  -> 找到目标 user
  -> 扫描到下一条 user 之前
  -> 存在非空 assistant text ? completed : system error
```

Gateway 会话投影和任务收敛必须复用同一纯函数。历史上任意 assistant、目标 user 之前的 assistant、下一回合 assistant、空白 text 和仅 reasoning/tool 均不能证明当前回合成功。`userMessageID` 缺失或找不到时按“不可证明成功”处理，并输出可重试、脱敏的错误，不得猜测。

控制器开始 monitor 时必须冻结 `{sessionId, turnID, userMessageID, generation}`。任何 status、turns 或 messages 响应在提交 Store 前重新核对这四个键；旧 turn 的 completed、旧 assistant 和旧 abort 响应不得关闭新 generation。409 接管成功后使用 Host 返回的真实键替换本地临时键，并立即执行一次 turns/messages 对账。

### 9.3 Gateway 启动任务恢复

```text
server listening
  -> scan goals once
  -> queued/in_progress 去重
  -> status + turns 对账
  -> 已有终态：立即收敛
  -> 仍活动：注册恢复监视
  -> 无活动且无终态：标记失败并给出可重试信息
```

`GET /office/tasks` 只读当前稳定投影，不能成为恢复触发器。重复 listening 回调、并发 GET 或热测试不得为同一 task 创建多个恢复器或重复通知。

### 9.4 paused、hidden、idle 和 FIFO 分离

```text
hidden=true  -> 只隐藏布局，动作和会话继续
paused=true  -> 停止 destructive GET -> 冻结 Dispatcher/Bridge/Scene
              -> 保留 mission/FIFO/dispatchLocked/wasMissionBusy/completedCount/agent state
paused=false -> 先恢复 Scene/Bridge/Dispatcher -> 再恢复动作 GET
              -> 从原 mission 进度继续 -> 完成一次 -> 消费下一条 FIFO
idle         -> 仅来自真实 set_state 或 mission 正常结束，不由 UI 控件伪造
```

暂停期间收到的新动作保留在 Gateway 队列，恢复后按 FIFO 取回。由于当前 `/actions` 是 destructive GET，本 CHG 采用“暂停时不 GET”的兼容方案；ACK/replay、跨 Gateway 重启恢复和多浏览器消费仍由独立动作协议 CHG 处理。

### 9.5 本地失败顺序和滚动锚点

本地入场前失败继续保存对应 optimistic user 与 system error，但 localStorage 升级为带锚点的 v2 envelope。远端历史刷新时按 `afterRemoteMessageId`、创建时间和 ordinal 稳定插入；旧 v1 数据按时间和原数组顺序迁移，不能统一追加末尾。幂等键是 `sessionId + localTurnOrdinal + messageKind`，禁止按“角色 + 全文”去重；两个不同回合即使得到同一条 503 文案，也必须各自保留。

滚动规则：

1. 首次选择 session、用户刚发送消息或更新前距离底部不超过 48px 时自动跟随底部。
2. 用户距离底部超过 48px 时记录首个可见 message id 和像素偏移；同值轮询、状态变化和新回复到达后保持该锚点，误差不超过 2px。
3. 用户阅读历史时新回复不得抢滚动；提供不改变内容高度的“有新消息”入口，用户触发后滚到底部。
4. 切换 session 时每个 session 分别保存滚动位置；隐藏/显示办公室不得重置当前对话滚动。

### 9.6 长助手正文和 Markdown 性能

测试 fixture 使用包含中文、emoji、CRLF/LF、引号、反斜杠、列表、代码块、链接和长难句的确定性正文，分别生成 50,000 与 180,000 UTF-16 code units，并记录 UTF-8 SHA-256。最新 user + assistant + terminal marker 必须作为一个原子回合整体保留；不能因浏览器缓存预算只留下部分回合，也不能让零正文的后置 completed marker 先占用预算并淘汰关联 assistant。单条最新 assistant 达到或略超预算时优先保留该最新完整回合，旧回合再按边界淘汰；预算必须覆盖已登记的 180K fixture 和协议开销，或采用不依赖硬编码正文长度的 turn-aware 保留策略。

完整性门禁分两层，不能混用：Provider 原文、Host assembler、JSONL、Gateway JSON 和 Store 原始正文执行逐字节 UTF-8 SHA-256 完全一致；纯文本消息的 DOM `textContent` 与原文精确比较。Markdown 渲染会合法改变 DOM 文本和结构，因此使用固定解析器版本下的规范化语义树、代码块/列表/链接数量、可见文本规范化结果和安全属性比较，禁止要求“原始 Markdown SHA-256 等于 DOM textContent SHA-256”这一不成立的条件。

2026-09-16 已确认两个独立故障。50K provider 原文长度 50000、SHA-256 `1df9604431a8093408ed7159a473bd226f66b11465071000efe89d31268fa194`，经过 OpenPaw SSE 后长度 50004、SHA-256 `920532cfed5980ae61ba76d73ea8b29e982c14c02032cd988afd01ed5a909aa5` 并出现 `U+FFFD`，属于 OpenPaw `CHG-2026-0013` 的上游阻断。180K JSONL 已存在长度 180004 的 assistant，但 `trimMessages()` 从最新消息逆序计预算时先保留空 completed system marker，随后发现 assistant 超过 `MAX_CACHED_TEXT_LENGTH=180000` 即退出，导致 Store 在 1s、3s、10s、30s 都只有 1 条 marker、assistant 长度为 0。该 Store 淘汰缺陷属于本 CHG，不能等待上游 UTF-8 修复来掩盖。

`AssistantText` 的解析结果按稳定 message id 与正文指纹缓存。status、queuePosition、pending、权限轮询和同值 messages 更新不得重新解析未变化的 Markdown。不得引入新 Markdown 依赖；现有安全链接白名单和纯文本转义保持不变。

### 11.2 兼容性

- 新增批量 status 是向后兼容只读接口；旧单 session status 保留。
- Office messages 响应形状不新增必填字段，但 `completed` 无正文从静默成功收紧为 system error。这是有意的可靠性修复。
- local notice v2 仅在浏览器 localStorage 内使用；读取 v1 时原地迁移，不能删除旧失败记录。
- paused 和 hidden 都不进入 Host、Gateway AgentState 或动作 schema。
- 不改变 provider、模型、OpenCode 路由、JSONL、任务 frontmatter 必填字段和 `/actions` 三种动作形状。

### 11.3 回滚

1. 回滚不得删除 session JSONL、goal、用户输入、本地失败记录或截图/性能证据。
2. 批量 status 可回滚为单 session 路由，但必须保留全活动恢复和请求预算；若无法同时满足，不允许部分回滚。
3. paused 修复不得回滚到“写六个 idle”或“setAgentState 清 mission”的版本。允许的最小安全回滚是停止动作消费并保留 Scene/Dispatcher 状态。
4. local notice v2 回滚前必须保留 v1 兼容读取，否则会丢失用户可见失败历史。
5. 长正文性能优化可以回滚缓存策略，但不得回滚正文完整性和 SHA-256 门禁。
6. 测试基础设施回滚不得重新引入未关闭 server、timer、AbortController、环境变量污染或依靠全局延长 timeout。
