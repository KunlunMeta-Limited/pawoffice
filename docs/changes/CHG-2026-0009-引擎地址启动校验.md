# CHG-2026-0009：Gateway 引擎地址启动校验

## 先说结论

本变更让 Gateway 在启动时严格校验 `OPENPAW_ENGINE_HOST_URL`，非法配置直接以中文错误和非零退出结束，不再静默回退到另一个本机实例。合法旧配置和缺省回环地址保持兼容，HTTP 路由与响应字段不变。该项涉及 L4 Gateway，正式批准和安全审核仍待 Git 平台记录。

## 2. 变更原因

旧 `engineHostOrigin()` 在 `OPENPAW_ENGINE_HOST_URL` 无效时静默回退到 `http://127.0.0.1:8787`。配置拼写错误会被伪装成引擎不可达，并可能连接本机另一个实例，破坏统一配置和失败语义。必须在 Gateway 创建前拒绝非法 origin。

## 9. 影响、数据流和实现

### 影响分析

合法配置和缺省配置行为不变。非法配置从运行后上游失败改为创建 Gateway 前明确失败，运维能直接定位错误。没有新增网络访问、重试或回退目标，不改变 CORS、路由、请求和响应。

### 数据流和失败路径

```text
进程环境变量 -> URL 解析 -> 协议/origin 约束校验
合法 -> 创建 Gateway -> 代理 OpenPaw Host
非法 -> 中文配置错误 -> 进程非零退出 -> 不监听端口、不发送请求
```

### 实现方案和选择理由

在单一配置入口严格解析 `URL` 并比较 origin 组成，避免用字符串拼接或捕获异常后静默回退。失败前置可防止错误配置连接其它本机服务，且比运行时模糊的“引擎不可达”更可诊断。
