## 2. 变更原因

当前 `OfficeAction` 只包含动作内容，没有来源会话、回合、任务、稳定事件编号、序号和时间。Host 使用有界 channel 的 `try_send`，队列满时动作可丢；Gateway `GET /actions` 使用 `splice(0)` 全局破坏性读取，第一个浏览器读取后其它消费者和刷新后的页面无法恢复。没有 ACK、cursor、持久化、去重、缺口检测和 snapshot，因此无法证明某个人物动画属于哪个对话，也无法在多会话、隐藏办公室、暂停、Gateway/浏览器重启后恢复一致状态。

六个物理人物是一个可见场景资源，不能同时展示四个会话互相冲突的位置和状态。本变更采用“每个 session/turn 独立逻辑投影，当前选中 session 映射到物理场景，后台 session 在会话列表显示真实运行态”的模型。切换会话时读取目标 session snapshot 和游标增量，不让后台会话抢占当前人物，也不停止后台模型执行。

## 9. 影响、数据流和实现

### 9.1 可靠传输和恢复

```text
OpenPaw event(sessionId, turnId, sequence, eventId)
  -> POST /actions/v2（失败用相同 eventId 重试）
  -> Gateway 整批校验 + journal fsync + eventId 去重
  -> 202 accepted
  -> Browser GET by consumer cursor（非破坏）
  -> 写入每 session 逻辑投影
  -> ACK 单调推进
  -> 当前选中 session -> Scene snapshot/delta
```

Gateway journal 只保存脱敏动画 envelope。先持久化再 202；重复 eventId 返回成功但不重复追加。journal compaction 必须保留每个 session 最新完整 snapshot、未被所有活跃 consumer ACK 的事件和诊断所需短窗口。浏览器发现 cursor 过旧或 sequence gap 时停止增量应用，读取 snapshot 后从 snapshot cursor 继续。

### 9.2 多会话到单一场景

```text
session A/B/C/D 各有独立 logical projection
  -> 最近对话显示各自 busy/queued/activity
selectedSessionId = B
  -> 只把 B 的六人 snapshot 和后续 delta 映射到物理 Canvas
切换到 A
  -> 递增 sceneEpoch，取消 B 的迟到 mission callback
  -> 原子 hydrate A snapshot
  -> A 后续 delta 继续动画
```

后台会话继续 ingest 和更新逻辑状态，但不移动当前 Canvas 人物。任务中心跳转只改变 selected session，并使用同一投影流程。一个事件只能更新其 `sessionId` 轨道；缺少 sessionId 的 v1 事件不得冒充真实会话。

### 9.3 hidden、paused 和 idle

- `hidden=true`：Canvas 不可见，但客户端继续消费 v2 并更新逻辑投影；不停止会话、不伪造 idle。重新显示时直接 hydrate 最新 snapshot，不补播不可见期间所有中间帧。
- `paused=true`：冻结物理 ticker 和 mission 进度；v2 事件仍可进入逻辑投影但不得改变当前帧。恢复时从当前 session 最新 snapshot 继续，旧 sceneEpoch 回调无效。
- `idle`：只来自当前 session 的真实 Host 状态或 mission 正常完成；UI 控件不能生成业务 idle。
- 无活动 session：所有人物保持 idle，无默认 walking/working/拜访。

### 9.4 失败和降级

动作投影失败永远不能改变 AgentLoop、task 或 turn outcome。Gateway 不可达时 Host 后台重试有界 outbox；超过保留上限必须记录脱敏诊断并保证最新 snapshot 可重建，不能阻塞 Provider。浏览器离线后用 cursor 续传；journal 已压缩时通过 gap + snapshot 恢复。v2 不可用时 UI 可以显示会话 busy 和文本状态，但不得回退到无因果 v1 动画并声称与真实回合一致。
