# CHG-2026-0011：多会话并行与真实任务联动修复

## 先说结论

本变更把对话运行态从组件级单例拆为按 session 独立的控制器和缓存，使 A 会话生成时可以切换、创建并运行 B/C 会话，迟到结果不会覆盖当前会话。任务深链、badge、最近对话、办公室显隐、后台刷新和动画初始状态同时收敛到真实 Gateway/Host 数据。它不把六名角色变为六个独立模型，也不在本 CHG 中升级动作协议或实现持久重放。

## 2. 变更原因

旧对话运行态是组件级单例，任一会话生成时其它会话不能正常切换，迟到响应可能覆盖当前会话；任务跳转使用永久 focus，手工选择会被拉回；任务数量只在部分导航加载；最近对话重复展示无价值元数据；场景初始状态和自动工作流在无真实任务时仍产生工作与拜访动画。后台刷新还会清空已成功数据，引发首页和智能体页面周期性抖动。

追加验收要求普通对话栏与其它右栏同宽，最近对话压缩为紧凑导航，对话中心可隐藏办公室但不能卸载画布或动作连接器，长回合只显示单一稳定状态，A 会话运行时创建 C 后 A 仍在后台独立完成。

## 9. 影响、数据流和实现

### 影响分析

对话选择只控制显示，不再拥有回合生命周期。每个 session 有独立消息、阶段、加载状态、活动工具、错误、pending、generation 和 AbortController。切换会话或离开对话中心不会取消其它 session；停止只作用于目标 session。后台资源刷新保留上次成功数据，首页、智能体和统计区域不周期性回到 loading。

任务深链改为递增 requestId，选择成功后消费，后续人工选择优先。权限按 sessionID 过滤；缺少归属的兼容项只在没有可识别归属时展示。初始角色全 idle，删除自动演示工作流；真实 set_state、desk_visit 和 desk_visit_tour 仍按 FIFO 投影。

### 数据流和失败路径

```text
selectedSessionId（只控制显示）
  -> useConversationController(sessionId)
  -> conversationViewStore[sessionId]
       messages / phase / messagesState / activeTool / error / pending / generation
  -> 每 session 独立 AbortController 与轮询
  -> Gateway 既有会话路由 -> OpenPaw Host

真实 Gateway action -> Dispatcher FIFO -> SceneBridge -> OfficeScene
无真实 action -> INITIAL_AGENTS 全 idle，不创建 mission
```

所有异步写回携带 sessionId 和 generation，旧 generation 不能覆盖新回合。删除活动目标会话时拒绝操作，但不阻塞其它会话。隐藏办公室只改变布局，不卸载 Canvas 和动作连接器，避免丢失运行中 mission。

### 实现方案和选择理由

采用按 session 的 store 和控制器，而不是一个全局生成标志，直接匹配 Host 的会话隔离模型。画布使用视觉隐藏而非条件卸载，保持动作队列和场景状态。动画只消费真实事件，不根据 UI 猜测工作状态。动作 v2、事件幂等和断线重放需要跨仓库设计，明确留待后续 CHG。
