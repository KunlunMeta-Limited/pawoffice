## 2. 变更原因

当前 B 线新增数据接口、动作服务和场景桥中有公共 export 没有标准中文说明，部分字段仍是英文短注释。不同 AI 无法从类型判断数据来源、写入权、FIFO、取消和失败隔离边界，容易绕过 Gateway 或重复实现动作协议。注释补齐只增加设计证据；MJS 公共函数因工具限制单独标记人工审查。

## 9. 影响、数据流和实现

### 影响分析

注释必须描述真实数据流：Host -> `/actions` -> Gateway 校验/队列 -> 浏览器轮询 -> Dispatcher/SceneBridge/Pixi；Dashboard -> `officeGatewayApi` -> `/office/*` -> 扫描或代理 Host。不得把内存名册说成持久化 agent，不得把 Office 投影失败说成引擎失败。

### 数据流和失败路径

```text
动作 POST -> Gateway 整批校验 -> FIFO -> GET 读后清空 -> 场景
面板请求 -> 类型化 API -> Gateway 扫描/代理 -> loading/ready/error
```

注释 PR 不增加 fetch、文件写入、队列操作或状态分支。

### 实现方案和选择理由

按项目内注释示例补齐公共 export 的 JSDoc；MJS 暂由人工按同一栏目审核，并在框架后续版本增加 JavaScript 检查器。选择先补 B 线公共边界是为了让跨项目协议和写入权先可读、可审查，内部 Pixi 算法另行处理。
