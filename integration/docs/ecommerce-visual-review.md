# 电商完整页面评审

> 内容归属已更新：交付物只保留文件和变更；预算与经营复盘在概览；商品文案从对应文件预览；验收在过程记录。协议字段见[用途与归属](./result-section-routing.md)。

目的：让业务数据经过真实接收接口进入正式办公室页面，评审任务概况、详情、成果和多轮更新的展示效果。不是只检查“文件能打开”。

人员复用办公室现有名册：王明统筹、李研编制计划、周理整理资料与构图、陈书编写文案、刘市核算预算和分析数据、赵审复核。mock 的员工数据通过 `sceneActorId` 绑定到对应人物，任务分配和成果负责人保持一致。

布局调整：概览先显示当前结论，移动端随后显示关键指标；任务目标独立收纳。主要交付物优先展示本轮新增和更新文件。交付物与过程记录顶部的“本页内容”可直接定位区块，折叠的过程区块会自动展开；图片缩略图完整适配原图比例。

保持原来的两个服务 `npm run dev` 和 `npm run integration-ui-example`。项目根目录另开 PowerShell 7，**先推荐全景模式**：

```powershell
pwsh -NoProfile -File .\integration\clients\start-workflow-mock.ps1 -Scenario ecommerce -Mode showcase
```

选择 **青禾电商运营室 · 模拟 · 全景第5轮 → 79元折叠支架上市准备**，点击工具栏 **当前成果**。无需先发消息，已载入五轮 prompt、回复、交付快照和文档版本。保持 mock 终端运行，文件正文和历史快照由这个模拟业务后端提供。

## 查看中间状态

先 Ctrl+C 停止之前的 mock，再运行下面命令。每次创建独立演示办公室，避免覆盖已有数据。

```powershell
# 第2轮：首版内容已交付，但经营数据尚未提供；预算3000元
pwsh -NoProfile -File .\integration\clients\start-workflow-mock.ps1 -Mode showcase -Round 2

# 第3轮：计划、文案和预算同步修订，能悬停查看3000→1800的逐行变化
pwsh -NoProfile -File .\integration\clients\start-workflow-mock.ps1 -Mode showcase -Round 3

# 第4轮：出现经营观察、数据图表、复盘结论，复核任务尚未完成
pwsh -NoProfile -File .\integration\clients\start-workflow-mock.ps1 -Mode showcase -Round 4
```

没有提供的数据不会补成经营业绩：前3轮没有经营折线与订单指标，只有商品事实和预算方案。

## 代码、CSV、JSON预览

重新启动mock后，同一办公室下还提供 **成果预览 · 代码 / CSV / JSON** 会话。选择这个会话，收起聊天，再打开“当前成果 → 交付物”：

- `预算核对示例.ts`：TypeScript高亮、完整复制、长代码折叠、自动换行。成果说明中的Markdown代码块也使用相同渲染器，Mermaid仍渲染为图。
- `搜索词观察明细.csv`：65条模拟记录，含前导零、引号、逗号、跨行备注。可搜索、分页、切换表头和分隔符；“源文”查看原始文本，“下载该版本”保留原始字节。
- `上市配置.json`：树状/源文切换、分支展开、全部收起。包含空值、布尔值及大整数，按原始数值文本显示。版本菜单可切换3000元的v1与1800元的v2，也可比较两版源文。

后端使用现有`artifacts`字段即可，无需新增协议类型：提供`title`、`mimeType`（如`text/csv`、`application/json`、`text/typescript`）、`content`或版本`url`，以及既有版本标识和可选哈希。文件正文按UTF-8解码。未知代码语言以纯文本显示，错误CSV/JSON显示原因并允许查看源文或下载。源码只读，不在浏览器执行。

这组附件用于预览能力评审，独立于主会话五轮业务流程；主会话仍保留原来的7份有效产物。

## 数据与边界

- 所有经营数据、协作和操作均为模拟。构图是SVG示意，非实拍。未接入真实店铺，不产生真实广告花费。
- 有效订单：12笔支付－2笔取消＝10；有效收入10×79＝790元；有效转化率10/600≈1.67%；预算1800－消耗360＝1440元。
- 逐日模拟数据的曝光、点击、订单、消耗加总与复盘一致。790－10×32－360＝110元仅为估算贡献，不是净利润。
- 最后一轮3项资料检查通过，但实测参数、实拍图和授权未完成，任务保持受阻。不会把资料验证当成已经上线。
- 历史快照及正文由mock内存保存，通过独立URL读取；没有写入用户项目工作区的版本仓库。Ctrl+C后这些地址不可用，重启创建新办公室。
- PawOffice目前为整个实例注册一个聊天后端地址。测试期间只在此演示办公室聊天；结束后由原业务后端重新注册原`chat.url`。这不改变两个原有服务的启动方式。
